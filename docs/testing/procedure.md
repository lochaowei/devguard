# 實際專案測試流程

每一輪實際專案測試（[Round 1](../real-project-test-report.md)、[Round 2](round-2-report.md)、[Round 3](round-3-report.md)）都照這份流程。報告寫成 `docs/testing/round-<n>-report.md`。

## 選專案

- 公開的 GitHub 專案，不在前幾輪的報告中。
- 每種語言數量相同，並優先涵蓋前幾輪沒測過的工具鏈變化（套件管理工具、型別檢查器、建置工具、hook 框架、monorepo 結構）。
- 記下每個專案的 commit SHA。

## 準備

- 受測的 devguard 用 `npm run build:exe` 產生，放進一個 bin 目錄並放在 PATH 最前面。`install` 寫的 git hook 呼叫的是 PATH 上的 `devguard`。
- clone 到 devguard repo 之外的目錄，避免巢狀 git 與 `GIT_DIR` 問題（#59）。
- Windows 上用 `git clone -c core.autocrlf=false`。Git for Windows 預設的 `core.autocrlf=true` 會讓沒有 eol `.gitattributes` 的 repo 出現大量 CRLF 格式誤報（#84），蓋過真正的 finding。要測 CRLF 行為時才另外用預設值 clone。
- 缺的工具在使用者範圍安裝，並在報告中記錄。安裝前先記下 `doctor` 怎麼回報缺工具。

## 每個專案的 9 步

```text
draft → check → fix --yes → check → check --full → install → doctor → commit（pre-commit）→ push（pre-push）
```

- `draft` 的 TODO 理由先填好再跑 `check`。草稿明顯不適用時（例如 Java 8 專案改用基線標準 `legacy@1.0.0`、誤判的元件），比照使用者審閱草稿的做法手動修改，並在紀錄中註明。
- pre-push 只推到本機 bare remote：`git init --bare <repo>.remote.git`，加成 remote `local`。`--depth 1` 的 clone 要先對 bare remote 設 `receive.shallowUpdate true`。**絕不推到上游，也不對上游開 PR。**
- pre-push 跑兩次：預設，以及 `DEVGUARD_PRE_PUSH=full`。
- 專案自己的 hook 失敗或擋路時，用 `SKIP=<hook id>` 觀察 devguard hook 本身的結果；devguard 的 hook 擋下 commit 時才用 `--no-verify` 前進到 push 步驟。兩者都在紀錄中註明。
- 每個 finding 都和直接執行該工具的結果對照，區分 devguard 的問題與專案或環境的問題。

## 開 issue

- 只有確認是 devguard 的問題才開。開之前先 `gh issue list --state all --search "<關鍵字>"` 查重（並行的 agent 可能剛開過），重複就在既有 issue 留言補充重現案例；也對照 `.out-of-scope/`。
- 內文第一行是 `> *This was generated by AI during triage.*`，接著 `來源：#<本輪 issue> Round <n> 實測`；標 `bug` 或 `enhancement` 加 `needs-triage`。
- 附上重現：專案、SHA、指令、實際輸出、預期。

## 紀錄與報告

多個 agent 並行時，每種語言寫一份片段，再由一個 agent 組裝成報告。片段格式：

```markdown
## <語言>

| # | 專案 | SHA | 結構／工具鏈特徵 | 標準 | draft | check 前 | fix --yes | check 後 | check --full | install | doctor | pre-commit | pre-push |
（每格：exit code｜finding 數與簡述，例如 `1｜3E 1D 2H`；沒跑寫原因）

### <owner/repo>
- 每一步的重點觀察，附關鍵輸出

### 發現的問題
- #<n> 標題 — 一句話（新開或既有）

### 環境備註
- 安裝了什麼工具、doctor 安裝前的回報
```

- 片段與報告不寫本機絕對路徑（clone、log、工具的安裝位置），用「本機 bare remote」「使用者範圍」這類描述。
- 用詞依 `GLOSSARY.md`（例如「基線標準」「元件」）。
- 報告結構參照 [Round 3](round-3-report.md)：方法、專案總覽、跨語言主題、issue 索引、結論、各語言詳細紀錄。
